01 — The Rename

From KidComs to KidSpace

KidComs described what it did when it was just a video call feature. KidSpace describes what it is now — a world kids can live in, even when they're not on a call. The name change is marketing and product positioning only. Internally, the codebase can remain "kidcoms" for backward compatibility with all existing database tables, API endpoints, and references.

The Vision in One Sentence

KidSpace is the place where children of separated parents stay connected to everyone they love — watching together, reading together, playing together, calling, messaging, doing homework — with the freedom of a real kids app and the safety rails that parents in high-conflict situations actually need.

What KidComs Was

  • Video calls via Daily.co
  • Text chat with ARIA monitoring
  • Circle management for approved contacts
  • Parental controls and call logging
  • Age-appropriate interfaces
  • Child wallet system

COPPA + COPPA+ compliance governs all of KidSpace. Every feature in this document must satisfy: (1) Verifiable parental consent before any child account is created, (2) No behavioral advertising or third-party tracking of children, (3) Data minimization — only collect what's needed for the feature, (4) Parental review and deletion rights for all child data, (5) No direct contact between children and strangers — all contacts are Circle-approved adults only. Model-agnostic. Rules-first. AI provides outputs. ARIA decides actions. Swap models without breaking behavior.
01 — The Core Architecture Principle

Rules-First. Model-Agnostic. Always.

The single most important architectural decision for ARIA: the AI model never decides what action to take. The AI model provides analysis and scored outputs — toxicity scores, classifications, rewrite suggestions. ARIA's rules engine reads those outputs and decides what to do. When you swap Claude for OpenAI or a future model, ARIA's behavior doesn't change. Only the quality of the analysis changes.

The Contract

ARIA owns the decisions. The AI model owns the output quality. The AI model receives an input, returns a structured JSON response matching a defined schema, and has no further involvement. ARIA reads the JSON, applies its rules, and executes an action. A score of 0.82 from Claude and a score of 0.81 from OpenAI both trigger the same ARIA rule — only the number changes, not the decision logic.

02 — The AI Model Contract

What ARIA Asks the AI — What It Must Return

Every AI provider ARIA works with must satisfy a defined contract: receive a standardized input, return a standardized JSON schema. ARIA never parses free-form AI responses — it only reads typed fields. This is how you swap models without breaking anything.

TypeScriptaria/contracts/TextAnalysisContract.ts
// What ARIA sends to ANY text analysis provider interface TextAnalysisInput { text: string // the message to analyze mode: 'parent' | 'kidspace' | 'professional' context?: string // recent conversation context (optional) language?: string // 'en' | 'es' etc. default 'en' } // What ARIA REQUIRES back from ANY provider interface TextAnalysisOutput { // Scores — all 0.0 to 1.0 toxicity_score: number hostility_score: number passive_aggressive_score: number controlling_score: number profanity_score: number // KidSpace extra fields (required when mode = 'kidspace') grooming_risk_score?: number distress_signal_score?: number // Classification primary_category: ARIACategory // top category categories: ARIACategory[] // all triggered requires_action: boolean // quick flag // Generated text (optional — AI can decline to produce) rewrite_suggestion?: string // only for parent mode rewrite_reasoning?: string // why it was rewritten // Provider metadata (ARIA logs this, never acts on it) provider: 'claude' | 'openai' | 'local' model_version: string confidence: number // 0.0 to 1.0 } type ARIACategory = | 'hostility' | 'blame' | 'passive_aggressive' | 'controlling' | 'profanity' | 'dismissive' | 'grooming_risk' // kidspace only | 'distress_signal' // kidspace only | 'clean'
Pythonaria/rules/decision_engine.py
# ARIA's rules engine — NO AI here. # This is deterministic Python code. # Changing the AI model never changes this file. from aria.contracts import TextAnalysisOutput, ARIADecision # Thresholds — configurable per mode THRESHOLDS = { 'parent': { 'suggest': 0.35, 'flag': 0.60, 'block': 0.85, }, 'kidspace': { 'suggest': 0.20, # extra sensitive 'flag': 0.40, 'hold': 0.55, # hold for parent review 'block': 0.70, 'end_session': 0.80, } } def decide( analysis: TextAnalysisOutput, mode: str, session_history: list[TextAnalysisOutput] ) -> ARIADecision: t = THRESHOLDS[mode] score = analysis.toxicity_score # Rules are evaluated in order — first match wins # KidSpace-specific rules if mode == 'kidspace': if analysis.grooming_risk_score and \ analysis.grooming_risk_score > 0.50: return ARIADecision( action='end_session', severity=4, reason='grooming_risk_detected' ) if score >= t.get('end_session', 999): return ARIADecision( action='end_session', severity=4 ) if score >= t['block']: return ARIADecision( action='block', severity=3 ) if score >= t['hold']: return ARIADecision( action='hold', severity=2 ) # Standard rules (parent + kidspace) if score >= t['block']: return ARIADecision(action='block', severity=3) if score >= t['flag']: return ARIADecision(action='flag', severity=2) if score >= t['suggest'] and \ analysis.rewrite_suggestion: return ARIADecision(action='suggest', severity=1) return ARIADecision(action='allow', severity=0)
◆

The key insight in this code: decide() is a pure Python function. It takes an analysis object (from any AI provider), applies hardcoded threshold rules, and returns an ARIADecision. It has zero API calls. It has no randomness. It always produces the same output for the same input. You can unit-test every possible ARIA decision without touching an AI model. When you upgrade Claude from claude-3-5 to claude-4, the decide() function doesn't change at all.

04 — ARIA KidSpace Guard Mode

Extra-Sensitive Mode — What's Different

KidSpace Guard Mode is ARIA operating at maximum sensitivity with two additional analysis categories not present in parent mode — grooming risk detection and child distress signal detection. Every threshold is tighter. Every action set includes session termination. Every event generates both a parent notification and an admin alert.

Video Guard Pipeline
Real-time frame analysis during KidSpace video calls
AWS Rekognition
  • Frame rate: 1 frame analyzed every 5 seconds by default. Escalates to every 1 second if a prior flag occurred in the last 60 seconds.
  • Moderation labels checked: Nudity · Graphic Sexual Activity · Explicit Nudity · Suggestive · Violence · Visually Disturbing · Rude Gestures · Drugs · Hate Symbols (swastika, etc.) · Weapons
  • Confidence threshold: Any label with confidence ≥ 70% triggers evaluation. Any label ≥ 85% triggers an immediate action.
  • Action matrix:
    · Nudity ≥ 85% → End Session + Flag Evidence
    · Violence ≥ 85% → End Session + Flag Evidence
    · Hate Symbol ≥ 70% → End Session + Flag
    · Drug-related ≥ 80% → Flag (don't end — may be educational context)
  • Evidence clip: When End Session is triggered by video, a 30-second clip (15s before + 15s after) is extracted, SHA-256 hashed, and stored as evidence. Neither parent can access this clip — only legal/admin.
  • Both parents notified within 60 seconds of any video-triggered session end
  • Attorney notified if the family file has an active attorney assignment
Audio Guard Pipeline
Continuous transcription + classification during KidSpace calls
AssemblyAI + Claude
  • Transcription: AssemblyAI streaming transcription — 10-second rolling windows. Real-time, not post-call.
  • Classification: Each 10-second transcript sent to Claude with the KidSpace Guard prompt. Returns scored JSON per the TextAnalysisOutput contract.
  • Extra categories in KidSpace mode:
    · grooming_risk_score — language patterns consistent with adult trying to build inappropriate relationship with child (excessive compliments about appearance, requests for secrecy, attempts to isolate child from parents)
    · distress_signal_score — child expressing fear, unsafe situation, asking for help indirectly
  • Grooming risk ≥ 0.50: Immediate End Session + Evidence extraction + Admin escalation. This threshold is intentionally low — false positives are better than missed detection.
  • Distress signal ≥ 0.60: Flag + notify both parents immediately with transcript excerpt of the flagged window. Do NOT end the call — child may need the connection. Parent can end it from their app.
  • Standard profanity/hostility: Flag at 0.40 (vs. 0.60 in parent mode). Parent notified.
  • Profanity from adult toward child ≥ 0.55: Session end + evidence + both parents notified.

06 — Swapping AI Models

How to Change Providers Without Breaking Anything

The entire architecture was designed for this moment. You want to upgrade from Claude 3.5 to Claude 4, or try GPT-5, or run a local model for cost reasons. Here's exactly what changes and what doesn't.

What Does NOT Change (Protected by Architecture)

  • The rules engine (decide()) — not touched
  • Threshold values in the config — not touched
  • All ARIA action types and their effects — not touched
  • The audit log structure — not touched
  • Database schema — not touched
  • All KidSpace safety behaviors — not touched
  • All parent-facing ARIA features — not touched
  • Compliance and legal posture — not touched
  • The JSON contract schema — not touched (only the prompt changes)

What DOES Change When You Swap Models

  • The ARIA_TEXT_PROVIDER env variable — from 'claude' to 'openai'
  • The prompt wrappers (system prompt format differs by provider API)
  • The API client code in aria/providers/{provider}.py
  • Score quality — a better model produces more accurate toxicity scores
  • Rewrite suggestion quality — better model = better rewrites
  • Intake summary quality — better model = more useful summaries
  • Cost — GPT-4o vs. Claude Sonnet have different pricing
  • Latency — different models have different response times

# This is the only file that knows what AI model ARIA is using. # The rest of ARIA never imports from this file directly — # it only calls analyze_text(), analyze_video(), etc. import os from aria.providers.claude import ClaudeTextProvider from aria.providers.openai import OpenAITextProvider from aria.providers.rekognition import RekognitionVideoProvider # Set in environment — swap without code changes TEXT_PROVIDER = os.getenv('ARIA_TEXT_PROVIDER', 'claude') VIDEO_PROVIDER = os.getenv('ARIA_VIDEO_PROVIDER', 'rekognition') # Provider registry — add new models here TEXT_PROVIDERS = { 'claude': ClaudeTextProvider, 'openai': OpenAITextProvider, # 'local': LocalModelProvider, # future } def get_text_provider(): provider_class = TEXT_PROVIDERS.get(TEXT_PROVIDER) if not provider_class: raise ValueError(f"Unknown ARIA provider: {TEXT_PROVIDER}") return provider_class() # Usage elsewhere in ARIA (provider-agnostic): # provider = get_text_provider() # analysis = await provider.analyze(input) # returns TextAnalysisOutput # decision = decide(analysis, mode, history) # rules engine # execute(decision, context) # action executor

Why This Architecture Matters Legally

ARIA's decisions are determined by code you wrote and control — not by a third-party AI model. When an attorney asks "how does ARIA decide to flag a message?" the answer is "our rules engine checks if the toxicity score exceeds 0.60 and the category includes hostility." That's auditable, explainable, and defensible in court. If you used an AI model to make the actual decision, you'd have to explain why an opaque model decided to end a child's call — which is nearly impossible to defend. Rules-first means you can always explain every ARIA decision in plain English, with the exact threshold and rule that triggered it.
