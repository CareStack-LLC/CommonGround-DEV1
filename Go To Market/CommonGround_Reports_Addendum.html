Gap Report 1 · Parent · Report P-7

Agreement Status Report

The one report that was clearly missing: a parent-facing document that shows where their SharedCare Agreement actually stands. Which sections are complete, which are pending co-parent approval, which have changed since last version, and whether they're living by it. Available on Plus. The single most-asked question in co-parenting disputes — "what does our agreement actually say?" — answered in one document.

REPORT P-7 · AGREEMENT STATUS REPORT
Parenting Agreement Status Report
Shows the current state of the SharedCare Agreement — section completion, approval status, version history, and a side-by-side comparison of ordered terms vs. actual practice. On-demand. Shareable with attorneys without being a full court package.
Plus — $17.99/mo NEW On-Demand
PDF export · No SHA-256 on Plus
SHA-256 optional on Complete
What's In It — All Fields
  • Cover: Both parent names, family file ID, report date, active agreement version number, agreement creation date, last signature date
  • Section Completion Table: All 18 SharedCare Agreement sections listed with status badge — Complete · Pending Co-Parent Approval · Draft (unsigned) · Not Started · Expired/Due for Review
  • Overall completion %: How many of 18 sections have dual-parent approval
  • Version history table: Every agreement version — version number, date created, who initiated the change, what changed (section name), current vs. prior parent approval status
  • Unsigned sections alert: Any section with single-parent signature but missing co-parent approval — highlighted with days pending
  • Key terms summary: From the signed sections — custody %, primary residence, exchange location, holiday rotation current year, child support amount
  • Ordered vs. actual comparison: For completed sections only — custody % ordered vs. actual last 90 days (pulls from P-4 data), exchange location ordered vs. GPS check-in location, holiday schedule ordered vs. calendar
  • Review due dates: Any sections with a scheduled review date within the next 60 days — flagged
  • Quick Accords log: Any temporary agreements created in the last 90 days — date, topic, both parent signatures, status
Data Sources (by field)
  • agreements — active agreement ID, version number, creation date, overall status
  • agreement_versions — full version history, initiating parent, change delta between versions, signature timestamps per parent per version
  • agreement_sections (implied from Agreement Builder) — individual section content, completion status, dual-approval flag, review date field
  • custody_periods — actual custody % last 90 days for ordered vs. actual comparison
  • custody_exchange_instances — GPS coordinates for exchange location comparison
  • schedule_events — holiday calendar events vs. agreement-ordered holiday schedule
  • quick_accords / agreements where type = 'quick_accord' — temporary agreement log
  • Key terms summary only appears for sections with status = 'complete' (dual-signed). Draft/pending sections show "Awaiting co-parent approval" placeholder.
  • Ordered vs. actual comparison requires ≥30 days of GPS exchange data. If insufficient data: "Not enough data yet — check back after 30 days of logged exchanges."

Gap Report 2 · Professional · Report A-7

Client-Facing Progress Summary

The attorney-initiated report sent back to their client. Not a court document — a communication tool. Firm-branded, one page, shows the client how they're doing on the platform. Builds client trust in both CommonGround and the attorney recommending it. The equivalent of a monthly bank statement: same data the client already has access to, arriving from the relationship that matters.

REPORT A-7 · CLIENT PROGRESS SUMMARY
Client Progress Summary
Attorney-generated one-page summary sent directly to the client. Firm-branded. Shows co-parenting health score, three key metrics, and a brief note from the attorney. Builds platform adoption and client confidence. Distinct from P-2 (parent self-generated) — this arrives from counsel.
Solo+ — $99/mo NEW On-Demand
PDF · No SHA-256
Attorney-branded
What's In It
  • Firm header: Attorney name, firm name, firm logo (if uploaded), date, client name, period covered
  • Co-Parenting Health Score: The same 0–100 composite from P-2 — one large number, trend indicator vs. prior period (↑ improving / → stable / ↓ declining)
  • Three Key Metrics block: (1) Exchange compliance % for the period · (2) ARIA constructive communication rate % · (3) Outstanding financial obligations count
  • What's working: 2–3 auto-generated bullet points based on data — e.g., "You completed all 8 scheduled exchanges on time this month" or "Your ARIA acceptance rate improved by 12% vs. last period"
  • Areas to watch: 1–2 auto-generated bullets for any metric in yellow/red territory — e.g., "2 expense requests have been in dispute for over 14 days — consider resolving before your next hearing"
  • Attorney note field: Free-text block the attorney fills in before generating — 3–5 sentences. If left blank, a default: "Your CommonGround activity is being monitored for your case. Please keep the platform updated."
  • Next step CTA: One action the client should take — pre-populated from system context (e.g., "Sign the pending Holiday Schedule section in your agreement" or "Log your last 2 exchanges to maintain your GPS record")
  • Footer: "This summary was prepared by [Attorney Name] using CommonGround. It is for informational purposes and does not constitute legal advice."
Data Sources (by field)
  • Health Score: same formula as P-2 — (exchange_on_time_rate × 0.40) + (financial_obligation_rate × 0.35) + (aria_constructive_rate × 0.25) — queried from custody_exchange_instances, obligations, message_flags
  • Exchange compliance %: custody_exchange_instances — on_time_status count for the period
  • ARIA constructive rate: message_flags — (total_messages - flagged_messages) / total_messages for the requesting parent only
  • Outstanding obligations: obligations where status = 'outstanding' or 'overdue' and due_date ≤ today
  • "What's working" bullets: rules engine evaluating metric thresholds. Exchange ≥90% → "completed all exchanges on time." ARIA rate ↑ >10% → "communication improving." Zero disputes → "no expense disputes this period."
  • "Areas to watch" bullets: rules engine for yellow/red metrics. Dispute age >14 days → flag. Exchange on-time <75% → flag. Health score ↓ >10 pts → flag.
  • Next step CTA: priority queue — (1) unsigned agreement sections, (2) unlogged exchanges, (3) overdue obligations, (4) pending Quick Accords. First item in queue becomes the CTA.
  • Attorney note: manually entered in portal — stored in professional_cases attorney_notes field, cleared after report generation
  • The attorney only sees their client's data — not the co-parent's individual metrics. Co-parent data appears only in aggregate percentages.

Gap Report 3 · Professional · Report A-8

GAL Child Welfare View

The report the platform has always been able to generate but never assembled into a child-focused lens. GALs, parenting coordinators, and child welfare advocates need a completely different view than attorneys — not parental compliance metrics, but child welfare indicators. Conflict exposure, connection maintenance, safety events. Available only to users with GAL or Parenting Coordinator access role on a case.

★

Access control is critical here. This report is only available to users with role = 'gal' or 'parenting_coordinator' on a case_assignment record. Neither parent, nor standard attorneys without GAL designation, can generate or view this report. The GAL access role requires dual-parent consent to grant. This must be enforced at the API layer, not just the UI.

REPORT A-8 · GAL CHILD WELFARE VIEW
Child Welfare Report (GAL / Parenting Coordinator)
Child-centered welfare indicators for Guardian ad Litem filing. Focuses on conflict exposure, child-parent connection health, KidComs engagement, and any platform-detected safety events. SHA-256 verified. Structured for direct court submission in child welfare proceedings.
GAL Role — Solo+ NEW On-Demand Only SHA-256 Verified
Dual-parent consent required
FRE 902(14) · Child-welfare focus
What's In It — All Fields
  • Cover: GAL name, case number, children listed by name and DOB, report period, both parent names, date generated
  • Conflict Exposure Score (per child): A 0–100 score representing how much platform-recorded high-conflict activity occurred during or proximate to the child's custody time. Lower = better. Calculated per child based on their custody schedule.
  • High-Conflict Events Near Exchanges: Any ARIA red or orange flag within ±2 hours of a scheduled custody exchange — timestamp, severity, which parent sent it. Message content not shown.
  • KidComs Connection Health (per child): Total calls in period, call duration trend, which parent initiated, any calls that were declined or cut short, flagged call count
  • Flagged KidComs Events: Any call where AI moderation triggered — type of flag (inappropriate content / hostile language / third-party interference), timestamp, duration of flagged segment, evidence clip reference (SHA-256 hashed)
  • Child-Parent Contact Compliance: Per SharedCare Agreement communication section — ordered contact frequency vs. actual KidComs call frequency, per parent
  • Exchange Environment Notes: Any exchange where GPS check-in showed non-approved location, exchange marked as "high conflict handoff" in the app, any QR scan refusal
  • Platform Safety Events: Any event in the audit log tagged as a safety concern — blocked messages, emergency contact activations, any parent-reported safety incidents logged through the app
  • Agreement Sections Relevant to Child: Status of sections directly affecting the child — Children (section 2), Communication (section 12), Child Contact (section 13), Medical (section 10), Education (section 11)
  • GAL Notes field: Free-text block for the GAL to add their own observations before generating the final PDF
  • Platform Attestation: CommonGround certification that all data represents unmodified platform records, with SHA-256 master hash
Data Sources (by field)
  • message_flags — severity ≥ 3 (orange/red) with timestamp comparison to custody_exchange_instances.scheduled_time ± 120 min
  • custody_periods — which parent had custody during each flagged message event (to calculate conflict exposure during child's time)
  • kidcoms_calls — all call records: initiating_parent, recipient, duration_seconds, ended_by, flag_count, flagged_clips array
  • kidcoms_calls.flagged_clips — evidence clip references with SHA-256 hash, flag_type, timestamp_in_call, duration
  • custody_exchange_instances — gps_coordinates compared to agreements exchange_location. exchange_type flag for "high_conflict" mode exchanges
  • audit_logs where event_type IN ('safety_event', 'emergency_contact', 'message_blocked', 'parent_reported_incident')
  • agreements.sections where section_id IN (2, 10, 11, 12, 13) — child-specific sections only
  • Conflict Exposure Score formula: sum of weighted_severity_scores for all flags during child's custody time ÷ total_custody_hours × normalization_factor. Weights: red_flag = 3, orange = 2, yellow = 0.5. Normalized to 0–100 where 100 = maximum recorded exposure.
  • Child-Parent Contact Compliance: count of kidcoms_calls per parent grouped by child_id in the period vs. contact_frequency value in agreements communication section
  • audit_logs — SHA-256 chain for the entire report
  • Per-child scoping: all metrics calculated per child_id, not per family_file. A family with two children gets two sets of conflict exposure scores.
  • GAL can only access data for cases where they hold an active case_assignment with role = 'gal' or 'parenting_coordinator'. Query is RBAC-gated at the database level via RLS policy.

Auth + Access Control

How Report Access is Enforced

Every report endpoint enforces access at three layers: JWT authentication, role check, and tier check. The GAL report adds a fourth layer: dual-parent consent verification. All three checks must pass — a valid JWT alone is never sufficient.

Python backend/app/services/report_access.py
async def verify_report_access( report_type: str, user: User, family_file_id: UUID, db: AsyncSession ) -> bool: # Layer 1: JWT already validated by Depends(get_current_user) # Layer 2: Role check ROLE_REQUIREMENTS = { "parent/snapshot": ["parent"], "parent/monthly-insight": ["parent"], "parent/agreement-status": ["parent"], "professional/case-compliance": ["attorney", "mediator", "paralegal"], "professional/gal-child-welfare": ["gal", "parenting_coordinator"], "professional/firm-analytics": ["attorney", "firm_admin"], } required_roles = ROLE_REQUIREMENTS.get(report_type, []) if user.role not in required_roles: raise HTTPException(403, "Insufficient role for this report type") # Layer 3: Tier check TIER_REQUIREMENTS = { "parent/snapshot": "free", "parent/monthly-insight": "plus", "parent/agreement-status": "plus", "parent/custody-analytics": "complete", "parent/court-evidence-package": "complete", "professional/case-compliance": "solo", "professional/gal-child-welfare": "solo", "professional/firm-analytics": "small_firm", } required_tier = TIER_REQUIREMENTS.get(report_type) if not user_meets_tier(user, required_tier): raise HTTPException(402, "Upgrade required for this report") # Layer 4: Case assignment check (professional reports) if report_type.startswith("professional/"): assignment = await get_case_assignment(user.id, family_file_id, db) if not assignment: raise HTTPException(403, "Not assigned to this case") # Layer 4b: GAL consent check if report_type == "professional/gal-child-welfare": if not assignment.consent_both_parents: raise HTTPException(403, "Dual-parent consent required for GAL report") return True

HTTP 402 on tier mismatch. When a parent on Web Starter hits a Plus-tier endpoint, return 402 Payment Required — not 403 Forbidden. One Note on Async vs. Sync

Reports that generate large PDFs — P-6 (Court Package), A-6 (Court Submission), and A-8 (GAL Report) — use async job generation: the POST returns a job_id immediately, and the client polls GET /reports/jobs/{job_id} until status = "complete". All other reports are synchronous and return the PDF URL directly in the response. For the three async reports, the polling interval should be 2 seconds with a 60-second timeout before showing a "taking longer than expected" message. These reports are typically done in 8–20 seconds depending on case size.
